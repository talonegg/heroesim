### v1.0.1-S4 · Shared places and the Bankruptcy countdown · 1 session · opus

**Shared places.** `rankings` (`engine/src/selectors.ts`) gives each Guild its own place, ties
ordered by Guild id, so a new game, every Guild at Fame 0, shows "1st of 5 by Fame" in the web's
header (`headerView`, `web/src/state/selectors.ts`), 1st to 5th in its Rankings (`rankingsView`,
`web/src/state/world-views.ts`) and Rank 1 to 5 in the CLI's `renderRankings` (`cli/src/render.ts`).
`rankings` stays, since the harness report and modules' `ctx.select` read it; a pure selector
beside it gives each a shared place, one more than the Guilds with a greater value, shown as
"joint 1st" (the CLI marks its Rank joint), rows in `rankings`' order.

**The countdown.** Each night `guildState` (`engine/src/phases/guild-state.ts`), after any Upkeep
due, sets `belowFloorSince` if Wealth is below `bankruptcyFloor` and clears it if not; `endingOf`
(`engine/src/phases/endings.ts`), later that night, ends the Guild once `dayOf(turn) >=
dayOf(belowFloorSince) + bankruptcyGraceDays`. DL-26 item 3 kept this silent because a front end
would read `belowFloorSince`; neither does. A second pure selector reads `belowFloorSince` alone,
the rule's own input, and gives `{ sinceDay, dueDay: sinceDay + bankruptcyGraceDays }` from the
game's own config (`playDeps(document).config` in the web), never a literal, or none when it is
null. While it is set the header says "below the floor since Day d: Bankruptcy on Day N's night
unless Wealth is at the floor or above at a night's check by then, after any Upkeep due", still
after Wealth rises during a Day (that night clears it); the CLI prints it after `advance` and in
`show`. No event and no stop (#32's, in v1.1): fast forward still runs through the grace, now
shown between steps (S5). `endings.ts` is unchanged; a test ties the selector to it.
