# v1.1.9 — The tests and the harness made faster and leaner, and the code's modules deepened

**Objective:** make the test suite, the harness and CI faster, and the tests leaner. Deepen the
modules where change keeps spreading across many files. Do all of it without changing play or
weakening what the tests protect.

Four read-only analyses of 2026-10-09 (§5) found that:
- a full local `npm test` takes 119–126 s, and most of that is contention between tests that start
  processes and browsers, not the tests themselves;
- half of every harness game is quest estimation, the Rivals' and the policy's;
- CI bills 22–44 minutes a push, `npm test` running twice in it and three times in a release;
- about 400 tests across the packages are duplicate, suspected redundant, tautological or slower than
  their assertion needs.

An architecture review of the same day (§5.1) found twelve places where knowledge of one thing is
spread across modules that keep changing together, or written twice. The owner took all twelve into
this release (QA c).

The owner's answers to Q1–Q30 and QA–QD (§6) set the scope. DL-231 and DL-232 record them.

**Sessions:** 25–31 (agent's estimate) · **Depends on:** `v1.1.8` released (pull request #59, merged

### v1.1.9-S4 · The Best Party module · 1.5–2 sessions · opus

The review's #1.

**Today**, `bestParty` builds a new `questEstimator` on every call (`rival.ts:525`). Five callers
reach it, none sharing any work: the Rival controllers (through `partyFor`, a pass-through), the
harness's policy (for every Quest, again after each dispatch), the page's Board (in its own
`useMemo`), the CLI's `render.ts` and `calibrate.ts`.

**The module.** One module is opened over one world, which does not change while it is open, and a
Guild. It answers two questions: the Best Party for a Quest from given Heroes, and a Party's chance.
It keeps the pool as it will come home and every Party it has already weighed.

**Lifetime** (Q20 as amended by QB a). It lives no longer than its world: one `rivalChoices` call,
one `automaticPolicy` call, or one document on the page. It is never module-global and never stored
in the document. The world's identity is its cache key.

**Callers.** All five use it, and `partyFor` is removed. S6's policy memo (a Quest's choice kept
when none of its Party was sent) is this module's reuse.

**Then** (Q20 b), if the profile still shows the estimate on top: pruning the search for a Party,
which must choose the same Party, ties included (ADR-0010).

**Acceptance:**

- [ ] `neutral --expect` identical, alone.
- [ ] A session used across a change of world fails.
- [ ] The five callers on the module, and `partyFor` gone.
- [ ] The profile before and after; the Rivals' share of a game recorded.

## 5. The analyses' findings (2026-10-09)

Four read-only analyses of the repository at `26cd276`. One measured, running each command alone.
Three read the tests of the engine, of web, cli, words and content, and of the harness and tools.

**The suite.**
- *Totals.* 231 files and 6,102 tests, 119–126 s wall. Of that time, tests are 67–69%, import 16%,
  transform 9–10% and environment 6–7%.
- *Contention.* Each project run alone, one after another, totals 207 s, so running them together
  gains only about 1.7×:
  - the editor's page test takes 2.4 s alone and 41 s in the full run;
  - `cli`'s transform takes 13.5 s alone and 48–53 s in the full run.
- *Where test time goes.* The tests add up to 1,748 s. Half of it is in 98 tests, and 4,663 tests take
  under 0.1 s each.
- *The slowest tests:*
  - `harness/src/write-once.test.ts`, 72 s;
  - the editor's page test, 41 s;
  - `owner.test.ts`, 38 s and the local run's tail;
  - the portrait tool's convert, 30 s;
  - the web reducer's year of steps, 24 s;
  - the engine's world-copy, 23 s;
  - dispositions, 22 s.
- *The bundle test.* `bundle.test.ts` runs 5 `vite build`s, 40–46 s; one build takes 1.8 s.

**Coverage** (v8, 2026-10-09).
- *Overall.* Lines 97.7%, branches 88.2%.
- *Per package.* The engine 99.8% / 95.4%; `cli` 95.2% / 82.2%; the portrait tool 95.3% / 76.4%.
- *Untested.* Only the five entry points are uncovered.
- *Caveats.* Code run only in child processes is not counted. 5–19 tests fail under coverage, all of

**One game** (20 years, alone, profiled).
